# AML — обнаружение отмывания в транзакциях

Исследовательский ML-проект на IBM Transactions for Anti Money Laundering:
временные признаки, ordered target encoding, сравнение моделей, выбор порога и анализ drift.

**Полный эксперимент:** XGBoost, test AP **0,3739**, precision **67,61%**, recall **31,96%**.
При выбранном пороге — 355 алертов, из них 240 истинных. Это baseline приоритизации,
а не готовая система полного покрытия отмывания.

[Результаты и выводы с графиками](reports/full/RESULTS.md)

## Структура

```text
notebooks/                  # Основные notebooks, outputs полного обучения сохранены
src/aml/workflow.py          # Вспомогательные функции признаков, OTE, split и метрик
src/aml/data/load.py         # Публичные функции загрузки данных
tests/                      # Проверки изоляции запусков, временных окон и метрик
reports/full/               # Публикуемые CSV, JSON, графики и выводы полного запуска
docs/                       # Данные, ревью и проверка миграции
```

Обучение моделей, Optuna, EDA и оценка остаются в notebooks.
`data/` и `artifacts/` — локальные директории, исключённые из Git.
Временная папка `notebooks_up` объединена с проектом; её резервная копия сохранена
локально в `artifacts/archive/notebooks_up`.

## Установка и данные

Требуется Python 3.13+; использованное окружение зафиксировано в `uv.lock`.

```bash
uv sync --locked --extra dev
```

Скачайте [IBM AML dataset](https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml/data)
и поместите `LI-Small_Trans.csv` в `data/raw/`.
Если существует `data/processed/raw.parquet`, загрузчик использует его приоритетно.
Датасет и обученные веса не включены в репозиторий.

Полный сохранённый эксперимент использовал локальный raw Parquet; равенство его содержимого
с заново скачанным CSV отдельно не подтверждено. [Подробнее о данных](docs/dataset.md).

## Проверка и запуск

```bash
uv run --locked --extra dev python -m pytest -q
uv run --locked jupyter lab
```

Откройте notebooks и выполняйте 01 → 05 в окружении проекта:

1. `01_eda.ipynb`: EDA и выводы по train.
2. `02_feature_engineering.ipynb`: признаки, сравнение кодирования, новый набор splits.
3. `03_training.ipynb`: обучение, Optuna, выбор champion.
4. `04_evaluation.ipynb`: порог, test и анализ ошибок по сегментам.
5. `05_data_drift.ipynb`: PSI с оговорками о сопоставимости периодов.

Данные всегда загружаются полностью. Отбор отрицательного класса при fit сохранён как
часть методики обучения с inverse-probability weights; это не режим загрузки части датасета.
Полный запуск требует значительного времени и RAM: исходный набор содержит 6,9 млн строк.

02 создаёт `artifacts/runs/<timestamp_uuid>`. После успешного экспорта указатель `active.json`
выбирает этот набор для следующих notebooks. Каждый запуск 03 создаёт отдельную папку
`training/<timestamp_uuid>`: все кандидаты, configuration.json, Optuna SQLite и таблицы trials.
Только после успешного обучения обновляется `active_training.json`.
04 сохраняет результаты в отдельную `evaluations/<timestamp_uuid>`, 05 — в `drift/<timestamp_uuid>`.
Старые эксперименты не перезаписываются.

Для выбора конкретного набора запустите Jupyter с переменной окружения, например:

```bash
AML_RUN_DIR=artifacts/runs/full uv run --locked jupyter lab
```

Без указателя нового запуска используется сохранённый `artifacts/runs/full`.
При ручном повторении ячейки записи в рамках уже открытого запуска работают с его папкой;
для отдельного эксперимента начинайте notebook с первой ячейки в новом kernel.

`06_temporal_backtesting.ipynb` запускается отдельно: три временных окна development-периода,
новый OTE в каждом fold, фиксированные параметры LightGBM/XGBoost и дневной бюджет алертов 0,1%.
Результаты сохраняются в `artifacts/backtests/<timestamp_uuid>`.
Backtest выполнен: XGBoost лучше LightGBM во всех трёх окнах.
[Метрики и выводы](reports/backtest/RESULTS.md). Это ретроспективный эксперимент, не новый holdout.

Outputs 01–03 относятся к сохранённому полному эксперименту. Новые поля конфигурации и
история Optuna появятся при следующем обучении; прежние trials восстановить из одних
итоговых метрик невозможно. Публикуемый `reports/full` остаётся снимком прошлого запуска.

## Протокол и ограничения

Периоды train/validation/threshold/test: примерно 70/10/5/15% строк с границами timestamp-пакетов.
Validation выбирает модель; отдельный threshold-период выбирает F1-порог; test оценивает
одного champion. В исходных данных нет времени получения меток: OTE предполагает их
немедленную доступность и пока является offline-экспериментом.

После просмотра текущего test дальнейший подбор требует нового holdout. Scores модели
не объявляются откалиброванными вероятностями. Высокий PSI календарных признаков частично
связан с разной длиной периодов, а не обязательно с ухудшением модели.
